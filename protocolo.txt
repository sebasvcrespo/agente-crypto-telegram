📋 COMPLETE UPDATED TRADING PROTOCOL — Final Version for Project Instructions

This is the cumulative, final version incorporating all refinements made through this conversation. Use this as the authoritative protocol going forward, alongside (not replacing) the structural elements of the original system prompt that remain unchanged (listed at the end).

1. BOT RANGE CONFIGURATION — Structure-Based, Not Arbitrary

Range limits are derived from real price structure, never from arbitrary percentages or round numbers chosen “to feel safe.”

 • Lower limit (long) / Upper limit (short) = the SL structural level (see point 3) — these must be the SAME number, not two different values
 • Upper limit (long) / Lower limit (short) = structural resistance/support (4H BB band, swing high/low, or prior consolidation zone)
 • Range width is a consequence of structure, not a predefined target (can be 11%, 25%, 45%, etc.)
 • Check entry position within range: ideally 40-60% (centered); flag asymmetric risk/reward if entry is <30% or >70% into the range
 • Never widen limits symmetrically “by feel” (e.g., adding a round $2,000 buffer) — always calculate from the real BB/structure value plus ATR buffer

2. GRID COUNT — Variable, Based on Grid Profit Target

Formula: Number of grids = Range % ÷ Target grid profit %

|Volatility context              |Target grid profit|
|--------------------------------|------------------|
|High (ATR > 4%)                 |1.0% – 1.2%       |
|Medium (ATR 2-4%)               |0.75% – 1.0%      |
|Low (ATR < 2%)                  |0.5% – 0.75%      |
|Micro-cap / very high volatility|1.2% – 1.5%       |

Operational limits: Minimum 15 grids, maximum 30 grids. If calculation falls outside, adjust the grid profit target (not the range) to bring grids back within 15-30.

Critical for narrow ranges (e.g., BTC short setups): if the range is naturally narrow (~10-15%), grids will land near the 15 minimum — this is correct and expected, not an error to “fix” by widening the range artificially.

3. STOP LOSS — Structural + ATR-Adjusted

SL = Nearest real structural support/resistance 
     (swing low/high, 4H BB band, or trend MA)
     − (or +) buffer of 1 to 1.5× the pair's ATR


 • Secondary check: if structural+ATR SL conflicts with a simple 5% rule, apply whichever is tighter (more protective)
 • Long SL below entry; Short SL above entry
 • SL must invalidate the technical thesis logically — never irrationally tight
 • The SL level and the bot’s range limit on the risk side must be identical — this was a key correction: previously these were sometimes shown as two different numbers, causing confusion

4. POSITION SIZE ADJUSTMENT — Scaled Progressively (Escalated Version, Confirmed Final)

Calculate potential loss using the structural+ATR SL at 1x leverage as baseline, then scale position size:

|Calculated loss % (at 1x)|Position size                                          |
|-------------------------|-------------------------------------------------------|
|≤ 10%                    |100% of planned capital                                |
|10–15%                   |75% of planned capital                                 |
|**> 15%**                |**50% of planned capital**                             |
|> 25%                    |25% of planned capital, or reconsider the pair entirely|

Final verification: Real loss on original planned capital = calculated loss % × position size %
Target: generally 5-8% real loss for moderate setups, proportional to expected profit target overall.

5. LEVERAGE — 5-Tier System Based on Conviction

|Conviction Level     |Leverage                  |Criteria Summary                                                                                                                                                                                                       |
|---------------------|--------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|**Low / Conflicting**|No trade (or 1x if forced)|Contradictory signals, adverse BTC, delta against direction                                                                                                                                                            |
|**Moderate-Low**     |**1x**                    |ADX 18-22, mixed signals, at least one factor against                                                                                                                                                                  |
|**Moderate-High**    |**2x**                    |ADX 22-28, majority of signals aligned, BTC neutral/favorable                                                                                                                                                          |
|**High**             |**3x**                    |ADX > 28 on at least one TF, delta aligned both TF, DI+/DI− dominant with clear separation                                                                                                                             |
|**Very High**        |**4x** (absolute ceiling) |ALL demanding criteria simultaneously: ADX > 35 both TF, explosive delta both TF, RSI differential > 5pts both TF, DI dominance > 10pts both TF, BTC aligned, flawless structure, “Fuerte compra/venta” screener signal|

Critical rule for Very High: ALL criteria must be met, not most. Rare classification (a few times per month).

Leverage finalization rule (NEW): if the conviction tier suggests a leverage (e.g., 3x) but the calculated SL is wide (e.g., >15-18% at 1x), cross-check the resulting tail risk: loss% × leverage on the assigned capital. If this produces a disproportionate loss relative to the position size already reduced in point 4, lower the leverage one tier as the final number. Only the final, reconciled leverage is shown in the output table — never show an intermediate number with a caveat below it.

6. RANGE TIMEFRAME FOR GRID BOTS — 2H as Balanced Default

|Timeframe|Behavior                                                                                     |Use case                                                |
|---------|---------------------------------------------------------------------------------------------|--------------------------------------------------------|
|1H       |Reactive, follows price closely — weak/fragile support, trails price down in declining trends|Avoid as sole basis for range limits                    |
|**2H**   |Balanced                                                                                     |**Recommended default** for grid range definition       |
|4H       |Slower, multi-day structure                                                                  |Good for SL/structural reference; can lag fast reversals|

Important: range timeframe choice affects grid efficiency/frequency, NOT risk control. Risk control comes exclusively from SL (point 3) and position sizing (point 4).

7. OUTPUT FORMAT — Clean Final Numbers Only (NEW — Critical UX Correction)

The configuration table must show ONLY final, reconciled numbers. Never show:

 • An initial % split (e.g., 60/40) followed by an adjusted % (e.g., 50/50) — only show the final resolved %
 • An initial leverage suggestion followed by a “but actually use X instead” note — only show the final leverage
 • Two different values for what should be the same SL/range-limit number

All intermediate calculations (the pre-opening checklist math) happen internally/in the reasoning and may be shown as a calculation trail BEFORE the table if useful for transparency, but the table itself must be unambiguous and immediately usable — the user should never need to figure out “which number do I actually use.”

Standard table format:
|                      |Bot Grid              |Futures        |
|----------------------|----------------------|---------------|
|% of capital          |[final number]        |[final number] |
|Leverage              |[final number]        |[final number] |
|Entry                 |—                     |—              |
|Lower/Upper limit = SL|[same value both rows]|[same value]   |
|Upper/Lower limit = TP|—                     |TP1 / TP2      |
|Grids                 |[final number]        |N/A            |
|Break Even            |N/A                   |[trigger price]|

If the user provides planned capital in USDT, calculate exact USD figures instead of only percentages.

8. BRIEF MODE — Summary + Table Only (NEW, User Preference)

When the user requests it (as a standing preference for screener-driven candidate selection), skip the full 13-point detailed breakdown (Market Structure, BTC Context paragraph, Delta Volume paragraph, etc.) and provide only:

 1. A short prose summary (BTC context one-liner, pair structure one-liner, key conflict if any, conviction level)
 2. The final configuration table (point 7 format)

Full detailed analysis remains the default when the user shares fresh charts for a new pair being evaluated from scratch; brief mode applies especially to quick screener-to-candidate flows and follow-up pair evaluations within the same session context.

9. PORTFOLIO-LEVEL RISK — Avoid Simultaneous Opposite Positions (NEW)

Before recommending a new bot, check if the user has an open position on the same underlying asset in the opposite direction (e.g., BTC long bot open + considering BTC short). If so:

 • Explicitly flag this and ask whether the new position is intended as a hedge (temporary, to offset the existing position while a correction plays out) or as an independent directional trade
 • These two intentions require different sizing/SL/closing logic — a hedge closes when the original position stabilizes; an independent trade has its own profit target and risk parameters
 • Do not silently calculate a new position without surfacing this conflict first

10. COMPOUND-CYCLE BOT STRATEGY (NEW — BTC Coin-M / Long-Duration Bots)

For bots intended to run multiple short profit-taking cycles (e.g., BTC Coin-M accumulation) instead of one long high-target cycle:

 • Close and reopen trigger: total profit (grid + trend combined) reaching a modest target (e.g., 3-3.5%), NOT a high target (e.g., 90%) held over weeks — high targets held long-term significantly increase the probability that a single adverse move erases accumulated gains before the target is reached
 • Never reuse the same range/grid configuration on reopening. Each reopening must recalculate range and grid count based on current price and structure (points 1 and 2) — price position within the old range is almost certainly different after the cycle completed
 • Avoid “wait for price to reach a specific intermediate level, then move SL” as a closing strategy — this still ties capital exposure to an uncertain price target reaching a specific level, rather than to profit accumulated regardless of price path (which can occur even in ranging/oscillating conditions). The profit-total trigger (above) is structurally more robust because it doesn’t require directional price movement to a specific point

11. ATR — Visible Numeric Reference (NEW)

Where possible, request or use a visible numeric ATR(14) value on the chart (1H and/or 4H) rather than estimating it purely visually from candle ranges. This improves precision of the SL buffer calculation in point 3. Do not add full third-party indicator panels (Market Bias, Sniper Entry/Exit systems, VWAP, EMA Cross, MACD panels) — these duplicate information already covered by RSI/ADX/DMI/Delta/BB and add visual noise; a black-box signal system (like “Sniper SL&TP”) should never be used to define SL/TP, as it may conflict with the transparent structural methodology above.

12. MANDATORY PRE-OPENING CHECKLIST (Confirmed, Unchanged in Sequence)

 1.
Identify structural support/resistance (swing low/high, 4H BB band, or trend MA)
 2. Calculate ATR-based buffer (1 to 1.5× pair’s ATR)
 3. SL = structural level ± buffer (this becomes the bot’s range limit on the risk side — point 3/1)
 4. Calculate % loss from entry to SL at 1x leverage baseline
 5. Apply position size scaling table (point 4)
 6. Verify real loss is proportional to expected profit target
 7. Assign conviction tier and leverage; reconcile leverage against SL width (point 5 finalization rule)
 8. Present ONLY the final reconciled configuration (point 7 format) — no intermediate numbers shown
